# ADR-0006: Изоляция виртуальным столом, не виртуальной машиной; режим выбирается

- Статус: принято, затем изменено по результатам спайков (см. «Пересмотр» ниже)
- Дата: 2026-11-02
- Связано: ADR-0002, ADR-0003

## Контекст

Требуется, чтобы агент по умолчанию работал там, где он не мешает человеку, а
при желании человека — на реальном столе, с наблюдением и участием. Виртуальная
машина отвергнута заказчиком: накладные расходы и отсутствие реальных
приложений пользователя и его логинов.

Проверка подтвердила правоту этого отказа и добавила аргумент: у VM по
умолчанию нет GPU-ускорения, поэтому игры и DirectX-приложения там деградируют,
а Windows.Graphics.Capture и захват рабочего стола работают иначе. Для цели
«абсолютно всё, включая игры» VM хуже, а не лучше.

## Решение

Целевое окружение выбирается, а не задаётся жёстко. Три режима.

**Реальный стол пользователя.** Агент владеет курсором на том столе, где
работает человек. HUD-рамка и перехват физического ввода активны. Применяется,
когда человек хочет наблюдать и участвовать, а также для любых целей Класса A,
требующих GPU: игры, DirectX, аппаратно-ускоренные приложения.

**Отдельный виртуальный стол** (документированный `IVirtualDesktopManager`).
Агент работает только Классом B, человек свободно пользуется своим столом.
Визуальный маркер — трей-иконка с анимацией состояния и уведомления.

**Скрытый desktop** (`CreateDesktopW`). Отличается от виртуального стола тем,
что пользователь не может случайно на него переключиться: его нет в панели
переключения столов. Доступен через `SetThreadDesktop` потокам демона.

VM остаётся опциональным четвёртым режимом для задач, где нужна полная
изоляция и где приложения пользователя не требуются.

Неоновая рамка HUD появляется на том столе, которым агент владеет, и служит
индикатором в режимах захвата.

## Последствия

Виртуальные столы **не дают изоляции ввода**: это группировка окон в той же
сессии с той же очередью ввода. Изоляцию ввода обеспечивает не стол, а Класс B
(ADR-0002). Смешение этих двух понятий — главная ошибка, которую предотвращает
данный ADR.

Маркер «агент работает» нельзя сделать окном, закреплённым на всех столах,
документированным API. Требуется недокументированный COM из `explorer.exe`, а
эта машина работает на Insider-сборке 28000, где такие интерфейсы ломаются
между сборками чаще всего. Трей и уведомления выбраны как надёжная замена.

Доступность `IVirtualDesktopManager` на этой сборке не подтверждена: проверка
реестра по CLSID дала неоднозначный результат и была прервана. Подтверждается
спайком S3 вместе с фактической работоспособностью действий Класса B на окне
другого стола.

Цели, требующие Класса A и GPU, всегда исполняются на реальном столе и всегда
конфликтуют с человеком. Это неустранимо и должно сообщаться агенту как факт,
а не скрываться: параллельность доступна для Класс B, а не для всего.

## Пересмотр 2026-11-02 по результатам спайков

Статус: изменено. Два допущения выше проверены, и оба изменили решение.

### Что измерено

Доступность COM виртуальных столов на сборке 28000. Документированный
`IVirtualDesktopManager` зарегистрирован в `twinapi.dll`, инстанциируется и
работает: `IsWindowOnCurrentVirtualDesktop` и `GetWindowDesktopId` вернули
`S_OK`. Недокументированный `VirtualDesktopManagerInternal` отсутствует в
`HKCR`, `HKCU\Software\Classes` и `HKLM\Software\Classes`. **Создать виртуальный
стол программно нельзя** — можно только переместить окно на уже существующий,
который пользователь создал вручную.

Захват невидимого окна. Целевое окно с известным содержимым в отдельном
процессе, захват из другого процесса:

| Состояние цели | `PrintWindow` | `mss` по области экрана |
|---|---|---|
| Видимо, не перекрыто | содержимое цели | содержимое цели |
| Полностью перекрыто другим окном | **содержимое цели** | зелёный цвет перекрывающего окна |
| Свёрнуто | **чёрный кадр** | то, что было позади |

`PrintWindow` с `PW_RENDERFULLCONTENT` и с `flags=0` на свёрнутом окне дают
одинаково чёрный кадр; `GetWindowRect` при этом возвращает штатный
`(-32000, -32000)`.

Извлечение DIB приходит перевёрнутым по вертикали. Это было обнаружено только
потому, что проверка сравнивала оба варианта ориентации; при проверке одного
положения пикселей результат читался бы как «содержимое не то», и вывод был бы
обратным. Код захвата обязан переворачивать кадр явно.

### Изменённое решение

**Отдельный виртуальный стол больше не является требованием.** Класс B наблюдает
перекрытые окна корректно, а перекрытие — это и есть нормальное состояние, когда
человек работает поверх целей агента. Стол нужен был для визуальной опрятности,
а не для работоспособности, и его стоимость (недокументированный API для
создания, которого на этой сборке нет) не окупается.

Режимы окружения сокращаются до двух:

**Реальный стол пользователя** — основной режим. Цели агента работают как
обычные окна, человек перекрывает их своими. Класс B наблюдает и действует
сквозь перекрытие; захват экрана через `mss` применяется только когда цель
действительно видима.

**Скрытый desktop через `CreateDesktopW`** — для задач, где окно агента вообще
не должно мелькать у человека. Документированный API, доступен всегда. Требует
`SetThreadDesktop` в потоках демона и проверки, что захват там работает.

**Обязательное предусловие наблюдения: целевое окно не свёрнуто.** Это новое
требование, вытекающее из измерения, а не из предпочтения. Перед захватом окна
его состояние проверяется через `IsIconic`, и при необходимости окно
разворачивается — через `WindowPattern.SetVisualState(Normal)`, то есть действием
Класса B, не требующим ни курсора, ни фокуса.

`IVirtualDesktopManager` остаётся полезным и сохраняется в объёме: он даёт
`IsWindowOnCurrentVirtualDesktop` для диагностики и `MoveWindowToDesktop` для
перемещения окна на стол, который пользователь создал сам. Создавать столы агент
не умеет и не должен пытаться.

### Последствия пересмотра

Объём Фазы 4 уменьшается: управление виртуальными столами сводится к
диагностике и перемещению окон, без создания и удаления.

Появляется новое правило в цикле агента: разворот свёрнутой цели — обязательный
шаг перед наблюдением. Без него захват молча возвращает чёрный кадр, а чёрный
кадр неотличим от genuinely пустого окна, поэтому проверка `IsIconic` должна
быть явной, а не выводиться из результата.

Риск, который остаётся непроверенным: окно на другом виртуальном столе, созданным
вручную. По механизму оно ближе к перекрытому, чем к свёрнутому, но это
умозаключение, а не измерение. Проверяется отдельно, если режим с несколькими
столами вообще понадобится.
