# ADR-0003: Настраиваемая политика захвата канала ввода

- Статус: принято
- Дата: 2026-11-02
- Связано: ADR-0002, ADR-0004

## Контекст

Действия Класса B параллельны с человеком по построению. Действия Класса A
монопольно владеют единственным курсором, поэтому всегда конфликтны. Нужен
способ выбирать поведение под задачу: где-то человек хочет смотреть и
участвовать, где-то нужна длинная пиксельная рутина без помех, где-то человек
работает и агент должен вклиниваться в паузы.

Четыре взаимоисключающих режима здесь плохое решение: они смешивают два
независимых вопроса — кто инициирует захват и как долго агент держит курсор.

## Решение

Захват канала ввода описывается тремя ортогональными параметрами.

`grant` — как получается разрешение: `auto` (агент берёт курсор сразу),
`ask` (запрашивает и ждёт подтверждения), `idle` (ждёт N секунд без
физического ввода по `GetLastInputInfo`, затем берёт).

`hold` — сколько держит: `step` (одно действие и отпускание) либо `batch`
(весь пакет действий Класса A одним заходом).

`block` — блокировать ли физический ввод на время удержания через `BlockInput`.

Из комбинаций формируются пять пресетов:

| Пресет | grant | hold | block | Сценарий |
|---|---|---|---|---|
| `interactive` | auto | step | false | Человек смотрит и участвует |
| `batch-fast` | auto | batch | true | Длинные пиксельные рутины без риска |
| `batch-safe` | ask | batch | false | Рискованная задача, одно подтверждение на пакет |
| `polite` | idle | batch | false | Человек работает, агент вклинивается в паузы |
| `locked` | ask | step | false | Каждый шаг подтверждается |

Правило эскалации: **таблица политик может ужесточить пресет, но не ослабить.**
Если шаг разрешился в элемент уровня «необратимо», `grant` принудительно
становится `ask`, а `block` — `false`, независимо от запрошенного пресета.
Агент вправе запросить послабление, но не вправе выдать его себе.

Пресет закрепляется в трей-меню демона. Это вето человека, которое не проходит
через чат и не зависит от решения модели.

## Последствия

Обязательный предохранитель: watchdog, безусловно снимающий `BlockInput` по
жёсткому таймауту порядка 5 с и в `finally` каждого пакета. Если демон зависнет
с активной блокировкой, пользователь останется без ввода до убийства процесса.

Ограничения `BlockInput`, которые надо заложить сразу: не срабатывает из
не-elevated процесса при elevated активном окне; не срабатывает при открытом
UAC-промпте; Ctrl+Alt+Del не блокируется никогда.

Режим `idle` делает время выполнения задачи непредсказуемым, поэтому он не
должен быть пресетом по умолчанию для длинных задач.

Пакетное удержание курсора означает, что человек теряет мышь на несколько
секунд сразу, а не на всю задачу. Это приемлемо только для верифицированных
пакетов; право на пакет имеют лишь обратимые действия (ADR-0004).
