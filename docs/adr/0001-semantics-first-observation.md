# ADR-0001: Семантическое дерево как первичное наблюдение, кадр — по запросу

- Статус: принято
- Дата: 2026-11-02
- Связано: ADR-0002, ADR-0004

## Контекст

Текущая реализация возвращает снимок экрана шириной 1280 px на каждое действие
(`autopilot_daemon.py:313-444`). На двух мониторах этой машины это даёт масштаб
2.0× для основного (2560×1440) и 3.5× для режима «все мониторы» (виртуальный
стол 4480×1440), после чего мелкий текст для модели неразличим. Кроме того,
каждый шаг добавляет в контекст хоста изображение, а часть хостов картинки в
результатах tool-вызовов не принимает вовсе.

Эталонные harness'ы (Anthropic computer use, OpenAI CUA) пиксельные, потому что
рассчитаны на произвольное окружение без доступа к дереву доступности. У нас
такой доступ есть.

## Решение

Первичное наблюдение после шага — компактное текстовое дерево доступности:
роль, имя, состояние, `clickable point`, стабильный идентификатор элемента.
Скриншот возвращается только по явному запросу агента либо автоматически при
сбое привязки или неожиданном изменении экрана.

Каждому элементу снимка присваивается короткий идентификатор (`@e17`). Агент
адресует действия идентификатором, а не координатой. Harness резолвит
идентификатор по кэшированному снимку и перепроверяет, что элемент жив, по
RuntimeId.

## Последствия

Положительные: расход токенов на шаг падает на 1–2 порядка; исчезает
координатная математика, а вместе с ней ошибки DPI, масштаба и даунскейла;
действия начинают работать по свёрнутым и перекрытым окнам; проверка результата
встроена, поскольку элемент сам сообщает своё состояние.

Отрицательные: на canvas-поверхностях (Figma, игры, PDF-вьюеры, окна RDP, часть
Electron с отключённой доступностью) дерево пусто и пиксельный путь остаётся
единственным. Требуется явная политика переключения между ветвями, а не
неявная надежда, что дерево всегда есть.

RuntimeId не стабилен между снимками — нужна стратегия пере-резолва и явная
ошибка, если элемент исчез, вместо клика по устаревшей координате.
