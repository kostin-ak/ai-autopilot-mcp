# ADR-0002: Разделение действий на Класс A (очередь ввода) и Класс B (сообщения и UIA)

- Статус: принято
- Дата: 2026-11-02
- Связано: ADR-0001, ADR-0003, ADR-0006

## Контекст

В сессии Windows ровно один курсор, одна очередь ввода и одно активное окно.
`SendInput` помещает событие в очередь сессии, `GetCursorPos` возвращает
единственный курсор. Два независимых потока ввода в одной сессии невозможны ни
в одной редакции Windows.

Проверенные и отвергнутые пути к параллельности: вторая RDP-сессия на localhost
(Windows 11 Pro даёт одну интерактивную сессию, а в отключённой сессии окна
перестают рендериться); отдельный desktop через `CreateDesktopW` (входным может
быть только один desktop за раз); виртуальное HID-устройство (кормит ту же
единственную очередь — решает задачу неотличимости от железа, а не
параллельности); VM (нет GPU-ускорения по умолчанию, деградируют игры и
DirectX, приложения и логины пользователя пришлось бы заводить заново).

Текущая реализация целиком относится к Классу A: все действия идут через
`SetCursorPos` и `SendInput` (`input_controller.py:334-498`).

## Решение

Все действия делятся на два класса по тому, затрагивают ли они очередь ввода.

**Класс B — очередь ввода не затрагивает.** Работает с окнами не в фокусе,
перекрытыми, свёрнутыми и находящимися на другом виртуальном столе:
`InvokePattern`, `ValuePattern`, `TogglePattern`, `SelectionItemPattern`,
`ExpandCollapsePattern`, `ScrollItemPattern.ScrollIntoView`, `RangeValuePattern`,
`WindowPattern`, `TransformPattern`, `SetFocus`, `PostMessage`/`SendMessage`,
захват по окну через `PrintWindow` и Windows.Graphics.Capture, `TextPattern`,
Console API, браузер по CDP/BiDi, Office по COM.

**Класс A — монопольно владеет курсором:** `SendInput` для мыши и клавиатуры
(включая `KEYEVENTF_UNICODE`), `SetCursorPos`, `Alt+Tab`, клавиша Win, глобальные
хоткеи, а также любые цели, которые реагируют только на настоящие события:
игры, canvas, custom-drawn виджеты.

Правило выбора: всегда Класс B; эскалация в Класс A только когда зондирование
цели (`probe_target`) показало, что Класс B недоступен или неэффективен.

Ввод текста в поле выполняется через `ValuePattern.SetValue()`, а не через
клавиатуру и не через буфер обмена.

## Последствия

Класс B по построению параллелен с человеком: общего ресурса нет, поэтому
человек может печатать и водить мышью, пока агент работает. Отпадает
необходимость в перехвате ввода для всего пути по умолчанию.

Отказ от буфера обмена для ввода текста закрывает сразу три дефекта текущей
реализации (`input_controller.py:500-523`): потерю нетекстовых форматов буфера,
неработоспособность там, где Ctrl+V не является вставкой, и конфликт за
единственный глобальный ресурс. Заодно исчезает зависимость от раскладки RU/EN.

Клавиатура остаётся необходимой для приложений без `ValuePattern`, поэтому
Класс A не исчезает, а становится исключением. Его монопольность регулируется
отдельной политикой (ADR-0003).

Непроверенное допущение: захват окна, находящегося на другом виртуальном столе
или на скрытом desktop'е. `PrintWindow` шлёт `WM_PRINT` самому окну, WGC
работает с redirection surface, но DWM может не держать поверхность живой для
не-текущего стола. Проверяется спайком S2 до начала Фазы 2; если оба способа
дают чёрный кадр, архитектура изоляции пересматривается.
